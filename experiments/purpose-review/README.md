# Direction Check + Personal Playbook

Isolated functional implementation, October 3, 2026. This directory is owned by the Codex purpose-review work. Claude's shared app files, build output, deployments, navigation, and database are not modified.

## Run

From the Arc90 repository:

```sh
node experiments/purpose-review/serve.mjs
node --test experiments/purpose-review/core.test.cjs experiments/purpose-review/storage.test.cjs
```

Open http://127.0.0.1:5187. Set `PORT` to another unused port if necessary. The server listens only on loopback and serves an explicit asset allowlist, not repository contents. This is a local preview, not a phone-accessible production release.

No new dependencies, build step, API key, migration, AI calls, or analytics. The existing Arc90 brand asset is served read-only. Local fonts and no external resources.

## Functional Scope

- Multiple outcome measures, each associated with a goal title, unit, preferred direction, and comparison group.
- Record, correct, and delete dated measurements, including zero and fractional values. Reject future measurements and invalid data.
- Compare only observations in the current comparison group within the last 30 calendar days. Show latest versus previous, not a causal claim or a goal-attainment percentage. Same-day entries retain insertion order; editing a record does not create another.
- Seven-day effort selector consumes existing goal/habit/task/log shapes without mutating them. Counts `done` or `min` once per habit/day, excluding `skip`. Includes valid ancestor goal paths, rejecting missing, archived, cyclic, or over-deep paths.
- Save a decision and revisit date, edit it, mark it reviewed, or delete it.
- Record obstacle/context/response and explicit helped / did-not-help / unsure feedback. Correct or delete attempts. Forget a response with confirmation, including its attempts.
- Editing a response with feedback creates a new version. Old feedback stays attached to the original text. Metric goal identity and units cannot change once observations exist.
- Separate example and personal sandbox records. Example data is clearly labeled and never touches Arc90 account data.
- Reload persistence, export, explicit reset, recoverable corrupt-storage errors, quota rollback, and a same-key cross-window overwrite guard.
- Light/dark themes, reduced-motion support, native dialog focus containment, labeled forms, text measurement history, and 375px layout.

## Integration Contract For Claude

Do not copy the preview into the main navigation as another tab. Proposed home: Direction Check in Progress, Personal Playbook within Arc's weekly/journal review. Preserve Claude's current navigation and let the final owner wire it after review.

1. Load `core.js` as a regular script to get `Arc90PurposeReview`, or require it in Node tests. `empty`, `normalize`, `transact`, `direction`, `playbook`, and `effortForGoal` are pure. Save actions are `{type, record}`; deletes are `{type, id}`. `transact` requires `{today: localYYYYMMDD}`. IDs are generated by the caller.
2. Replace the sandbox's free-text goal field with an existing-goal picker. Pass goal IDs through unchanged. Do not create duplicate goals automatically.
3. Pass a read-only snapshot of existing `S.brain.goals`, `S.habits`, `S.tasks`, and `S.log` into `effortForGoal`. Verify the current live shapes before integration. Habit-to-task fallback is used only without an explicit habit goal. Removed habits cannot be attributed by this selector without a historical habit snapshot; do not present its count as complete historical accounting.
4. Store the versioned records under an explicitly owned, user-scoped state field using the app's commit/rollback path. The sandbox keys are deliberately unrelated to production storage and are **not** a sync implementation. Do not silently import them.
5. The current journal's remembered responses are not proof of helpfulness. Any import must be reviewed by the user and initially have no attempts. Never infer feedback from habit completion or free-text sentiment.
6. Associate a chosen adjustment with a task only after explicit user confirmation. This version does not rewrite today's plan or mark habits complete.
7. If cloud synchronization is added, scope records by authenticated user, add RLS tests and conflict handling, account switching, export, and deletion. No server migration or upload is included here.
8. Review CSS component by component against the current theme. `preview.css` styles a standalone page; do not load it globally into the live app.

## Storage And Limits

`storage.js` writes only after a complete validated transaction and rejects a stale baseline from another tab. This is a last-write guard, not distributed locking. No encryption or cross-device sync is claimed. Browser data clearing removes local records; JSON export is available, but import is not implemented.

The loaded page does not need a network API to edit records. There is no service worker, offline cold-open guarantee, automatic reminder, journal AI, causal inference, or health guidance. This first slice does not include the 90-Day Story, widgets, public marketing campaigns, or changes to the live app.

## A Marketing Test, Not A Launch Claim

Concept: **Consistent, but stuck?**

Three honest shots: the week's completed study actions; comparable outcome observations; the user's chosen adjustment. End on "Arc90. Make the effort count."

Second concept: **A hard day can leave you with a better plan.** Show an obstacle, the response tried, and the user's own verdict. A later day recalls that exact response with its actual history.

Label recordings from this workspace "Product preview / example data." Do not imply improved exam results, health outcomes, scientifically proven effectiveness, or market-wide novelty. No campaign was published or paid media purchased.
